# 躯干分割工作台

在浏览器选择原始数据目录和成果保存位置，点击按钮运行 SAM 2.1 批量分割；再打开对应成果目录，筛选、补画、擦除并保存。原始数据只读，输出目录与源目录必须相互独立。无需输入终端命令。

首次克隆、换电脑或准备提交远程，请先看 [模型下载与跨平台部署说明](DEPLOYMENT.md)。其中包含官方来源、固定提交、配置、权重 SHA256、Mac/Windows 安装启动、数据迁移及提交清单。模型信息保存在可提交的 `model_manifest.json`，权重不进 Git。

## 打开

完成首次安装后，Mac 双击 `启动SAM分割.command`（`启动分割.command` 也打开同一工作台），Windows 双击 `启动SAM分割.bat`。浏览器打开 `http://127.0.0.1:8768`，请保持启动窗口开启。Windows 启动脚本尚未经过 Windows 实机验证。

首次启动在页面选择任务，之后自动记住上次打开的成果目录。已有全量 SAM 初稿位于工作区 `outputs/itof_SAM2猪体分割/`，可通过“打开成果目录”选择；`outputs/itof分割试验/` 为旧 GrabCut 初稿。目录选择记录存放在程序的 `.state/settings.json`。命令行仍可用于维护，但日常操作都可在网页完成：

```sh
python3 app.py --source '/原始数据/itof' --output '/另外的输出目录' --open
```

原开发机的 OpenCV 和模型依赖分别位于 `.deps/`、`.model-deps/`。新电脑使用独立 `.venv`，安装 `requirements-sam.txt` 并运行 `prepare_models.py`；`requirements.txt` 仅含基础图像依赖，不包含 SAM 所需的 PyTorch 等包。仅本机运行，不会上传图片或掩码。

## 浏览器新建分割任务

1. 点击顶部“新建分割任务”。Windows 和 macOS 上各处“选择文件夹”均弹出系统文件夹选择窗口，可从侧栏浏览磁盘、选择目录；取消时保留原路径。覆盖原始数据目录、成果保存位置、打开成果目录、移动后的原始目录和导出位置。Windows 使用 Python 自带的 Tkinter，请保持安装了 Tcl/Tk 支持。也可直接在网页输入完整路径。其他系统使用网页目录浏览器。
2. 选择 iToF 或双目原始采集目录和“分割输入”：**红外图分割**需要 `infrared.npy`、`infrared.png`、`depth_mm.npy`；**RGB 图像分割**需要 `color.png` 和原采集的 `reconstruction.json`，使用其中实际彩色流和已保存对齐深度的 profile 进行几何校正。`depth_aligned_to_color_mm.npy` 用于深度统计和后续点云，缺少时只能分割图像。可选择所有猪的根目录，也可选择某头猪的目录。“检查数据”按所选模式统计可用采集并核对 RGB 标定。
3. 选择成果保存位置，填写一个新的成果文件夹名。每次仅创建这个指定的成果目录，不再自动创建参数试验目录。已有文件的目录会被拒绝，避免覆盖人工进度。
4. 点击“检查数据”查看猪只／采集数，再点击“开始分割”。页面显示当前采集、进度、成功数和失败记录。“停止任务”会在当前一帧完成后停止，保留已完成成果。
5. 完成后自动显示成果，也可点击“进入成果复核”。关闭浏览器不会中止后台分割，需保持本机服务运行。

新任务直接从原始数据临时计算 GrabCut 候选，为 SAM 提供单点或框提示；候选在内存中计算，不依赖旧成果文件夹，不生成单独的 GrabCut 输出目录。模型权重没有训练或更新。

每个成果目录固定一种输入，文件夹默认名包含 `IR` 或 `RGB`。要比较同一批采集的两种效果，请分别新建两个任务。打开已有成果会自动恢复其模式；旧成果没有 `input_mode` 字段时按红外处理，不会把旧掩码叠在 RGB 上。模式同时保存在 `dataset.json`、逐帧记录与导出 CSV 中。

红外成果主画布显示红外图，右侧为 RGB 参考；RGB 成果主画布显示校正后的彩色图，右侧为红外参考与 RGB 对齐深度。底图按钮、SAM 推理、笔刷、多边形、保存的叠加图均使用同一套坐标。RGB 深度统计只读取 `depth_aligned_to_color_mm.npy`，缺少时显示“—”并提示；尺寸错误会报错，不用缩放的原始深度替代。RGB 掩码不能直接套用 `depth_mm.npy` 生成点云。

### 为后续点云保留正确几何

RGB 先按实际彩色流的内参和畸变，重映射到已保存对齐深度的输出内参、畸变及完整尺寸，再送入 SAM。当前采集的对齐深度输出为零畸变，因此这一步包含 RGB 去畸变；不会另选“最优内参”、裁剪画面或修改原始图。已保存深度保持原值，不再重复做深度到彩色的外参变换。重映射超出原图的边缘标为无效，自动掩码会剔除，人工掩码含该区域时不能保存。

红外保持原始像素网格，只有实际红外／深度内参、畸变和相机位置一致才允许直接逐像素配对。生成点云时使用原始深度 profile 逆畸变得到射线，不能对有畸变的红外直接套简单针孔公式。RGB 点云位于彩色相机坐标系，红外点云位于深度相机坐标系，两者不能直接混合。

新成果每帧保存 `geometry.json`（坐标系、实际内参／畸变、深度文件、单位比例和源文件哈希）与 `image_valid_mask.png`；RGB 的 `color_display.png` 是校正底图。`segmentation.json` 同时记录几何版本和来源。导出筛选成果会保留这些文件；原始 RGB、深度及重建记录仍需单独保留。缺少标定的旧红外成果可继续修正，但不标记为可生成点云。

**以前直接用原始 RGB 分割的成果不会自动变成校正成果。** 打开时明确标为“旧 RGB 成果未校正”，保留查看、筛选和导出，关闭掩码编辑与 SAM；请用原始数据新建一个 RGB 任务。不能把旧掩码原样叠到去畸变后的底图上。

后续点云代码可调用 `geometry.backproject_mask(capture_dir, mask, geometry)`，返回 XYZ（毫米，X 向右、Y 向下、Z 向前）和对应 UV。它核对来源与几何版本，优先使用对应 sensor code 乘该帧单位比例，否则读取毫米深度，排除零／无效深度。确认掩码应读取 `trunk_mask.png` 并检查 `reviewed=true`。目前页面完成的是几何准备，尚未新增点云预览或 PLY 导出按钮。

## 打开成果与再次筛选

点击“打开成果目录”，选择包含 `dataset.json` 的成果根目录，再点击“载入成果并复核”。按该清单精确载入对应采集，12张试验不会扩展为162张。跨电脑复制或移动成果后，如果清单里的原始目录不存在，工作台会在成果目录的相邻位置，按原路径末尾的文件夹层级查找，并核对清单中的全部采集。唯一匹配的本地原始目录会自动记住；没有匹配或存在多个匹配时，请在页面填写新原始目录，保持原相对层级。成果清单和掩码不会因路径重定位被改写。

右侧“保留／淘汰／待定”保存当前成果的筛选结论，淘汰需填写备注。左侧按筛选结论过滤；顶部可下载当前目录的筛选记录 CSV。筛选记录在每帧 `segmentation.json` 的 `decision` 和 `decision_history` 中，关闭后重新打开仍然保留。筛选保留与掩码已确认分别记录：保留某帧不会自动批准掩码。

### 选择位置导出筛选成果

1. 保存当前画布或备注的修改，点击顶部“导出筛选成果”。
2. 选择范围：默认“已保留”，也可选“已保留且掩码已确认”、“已淘汰”、“待定”、“未筛选（已分割）”或“全部已分割”。页面显示将导出的猪只数和采集数。
3. 点击“选择文件夹”打开系统窗口选择保存位置，再填写新的导出文件夹名。导出位置会记住；已有目录会被拒绝，防止覆盖进度。
4. 点击“开始导出”，完成后显示实际路径。后台复制期间暂停编辑与切换目录，保持本机服务运行。

导出仅复制所选采集的分割掩码、叠加预览、逐帧 JSON、模型记录及修订历史，保留原猪只／采集层级，同时生成 `dataset.json`、`筛选记录.csv` 和 `export.json`。原始红外、深度、RGB 不复制，仍引用原始数据目录。导出的文件夹可用“打开成果目录”继续复核；筛选保留仍不会把初稿变为已确认掩码。筛选 CSV 位于所选导出目录；顶部的单独 CSV 下载遵循浏览器的下载设置。

分割运行时暂停编辑与目录切换，避免后台写入和人工修正冲突。多窗口中使用旧目录的保存请求会被拒绝，避免保存到另一个成果目录。任务状态在成果目录的 `batch_job.json`，服务意外结束后的未完成任务显示“任务中断”；已完成帧可继续复核，未完成帧可以手动运行 SAM 后保存，或新建分割任务。

## 人工修正

1. 左侧选择耳标与采集；可搜索耳标和时间，也可按状态筛选。
2. 绿色区域是当前掩码，选择“红外原图”或“RGB 原图”（随成果模式变化）检查真实边界，选择“二值掩码”检查最终黑白图。
3. 用“补画”恢复漏分区域，用“擦除”移除背景、头、耳、尾和腿。笔刷尺寸以原图像素为单位。
4. 大块区域使用“多边形补画／擦除”：依次点击顶点，按回车或“闭合轮廓”完成；Esc 取消。撤销、重做均可用。
5. 在图像坐标中记录头侧方向，填写必要备注。
6. 点击“保存修正，稍后确认”保留进度并停留当前采集；检查合格后点击“确认合格并保存”生成 `trunk_mask.png`。按钮上方的“确认保存后自动切换下一张”默认不勾选：勾选时，保存成功后打开当前相机／筛选／搜索列表中的下一张采集，同一耳标的其他采集也会依次打开；不勾选时停留当前采集。勾选偏好会在本浏览器中记住，刷新后保留。仅确认当前采集，同耳标的其他采集不会被批量确认。保存失败或列表中没有下一张时留在当前采集。

快捷键：B 补画、E 擦除、Ctrl/⌘+Z 撤销、Ctrl/⌘+Shift+Z 重做、Ctrl/⌘+S 保存修正、左右键切换采集。关闭或切图时，尚未保存的修改会提示。辅助参考图和深度图可点击放大，参考图不改变主画布的掩码坐标。

## 分割范围

标注目标是可见躯干，颈部截断规则在整个数据集中保持一致，尾巴从尾根处排除。遮挡处沿可见边界处理，不臆造缺失身体；严重遮挡、出画或姿态不适合的采集暂不确认合格，在备注说明原因。当前数据尚未人工筛选，生成分割初稿不等于图像采集质量合格。

旧版 GrabCut 使用红外亮度、深度范围和中心区域提示，辅以连通域与形态学处理。新版浏览器任务使用官方 SAM 2.1 预训练权重，GrabCut 仅临时建议提示点，不限制 SAM 边界。两种方法都没有用本数据训练或微调。中心区域只是目标选择先验，没有采用元数据里的旧固定引导轮廓作为真值。自动分割无法保证解剖学头颈／尾根位置准确。

## 输出与状态

保持原来的“猪只／采集”相对层级：

```text
输出目录/
├── dataset.json
├── summary.json                 # 初始批处理的统计快照
├── 分割记录.csv                 # 初始批处理的统计快照
├── source_inventory.json         # 批处理前的源文件大小和修改时间
└── pig_编号/采集时间/
    ├── infrared_display.png     # 拉伸亮度后的查看图；不改变原始像素坐标
    ├── trunk_mask_draft.png      # 自动初稿，0/255，未人工确认
    ├── overlay_draft.png
    ├── trunk_mask_working.png    # 保存修正后生成
    ├── overlay_working.png
    ├── trunk_mask.png            # 只有确认合格后才生成
    ├── overlay.png               # 只有确认合格后才生成
    ├── segmentation.json         # 当前权威状态、头侧方向、备注与源文件校验值
    └── revisions/00001/...       # 每次保存的独立修订记录
```

所有掩码都是单通道 PNG，前景 255、背景 0。红外掩码对应原始深度网格（iToF 示例为宽 640、高 576）；RGB 掩码对应已保存的对齐深度输出网格，尺寸以该帧实际 profile 为准。保存时拒绝错尺寸、灰度不规范、无效校正边缘和空掩码。修改已确认的结果后若仅保存修正，该帧会返回“待确认”，移除旧的合格文件，历史版本仍保留在 `revisions`。

后续处理应读取当前 `segmentation.json`，仅使用 `reviewed=true` 对应的 `trunk_mask.png`。掩码中的无效深度仍需在点云阶段排除；同尺寸本身不能替代红外／深度配准核验。`summary.json` 和 CSV 是批处理时的快照，人工修正后的实时状态以逐帧 JSON 和页面为准。

## SAM 2.1 猪体分割（新版）

启动工作台后打开本机 `http://127.0.0.1:8768`。首次在页面选择原始目录或已有成果，之后恢复 `.state` 记录的上次目录，不固定为历史试验目录。SAM 成果页面隐藏旧初稿生成按钮，提供真正的 SAM 2.1 点／框推理。

1. 选择“目标点 ＋”，在猪体内部点一下，点击“运行 SAM”。
2. 必要时用“背景点 −”点中误分区域，或“框选目标”拖一个宽松框。少量明确提示通常比在边界随意堆点可靠。点击“清空提示”可重新尝试，当前分割保留。
3. 模型只更新画布，检查后用笔刷移除头耳尾腿，再保存修正或确认。SAM 推理本身不会自动保存或确认。
4. 切图会清除提示；保存时保留本次 SAM 提示、模型信息及原始预测。自动批处理的尝试保存在 `model_attempts`；人工保存的原始预测随修订保存在 `revisions`。

模型：Meta 官方 SAM 2.1 Hiera Base Plus。可提交的固定版本、文件清单与校验值见 `model_manifest.json`；`prepare_models.py` 下载后也会生成 `.models/sam2/SOURCE.json`。权重为 `.models/sam2.1_hiera_base_plus.pt`，SHA256 写入逐帧 JSON。首次点击加载模型较慢，之后同一张图缓存图像特征。

红外模式将增强灰度复制为三个通道；RGB 模式输入校正到已保存对齐深度网格的三个彩色通道。未用这些猪的标注训练或微调。SAM 学习到的图像特征结合前景／背景点或框生成像素掩码；深度不直接输入 SAM。红外模式以红外和深度计算临时 GrabCut 候选；RGB 模式只以彩色图计算候选（先缩小至长边不超过 640 像素，再以最近邻恢复提示候选），失败时用中心点和宽松框。候选建议内部目标点，输出很小时改用宽松框重新推理，模型边界不受候选掩码裁剪。项目自身后处理只保留目标连通区域，不腐蚀边界，不主动填充遮挡孔洞；官方预测器另有默认后处理行为，详见部署说明。

批量命令（比较新设置请使用新的输出目录）：

```sh
python3 sam_batch.py --source '/原始数据/itof' --output '/独立的SAM输出目录' --baseline '/旧GrabCut输出目录'
```

自动结果只是“可见目标猪”初稿，头耳尾腿的取舍仍需人工统一。内部预测分数不是数据集实测准确率，没有人工真值前不报告 IoU 或 Dice。此前多个试验目录为参数探索记录；日常以页面顶部显示的“当前成果”目录为准。

### 按相机筛选与查看进度

复核页面左侧提供“全部 / iToF / 双目”相机筛选，显示各类采集数量，每条采集也带相机标签。根据采集相对路径（如 `itof-1110`、`双目-1110`）识别相机；无法识别的采集单独显示为“未识别”，不会默认归到某一种相机。相机筛选可叠加状态筛选和耳标／时间搜索，上一张、下一张和自动切换下一张均使用当前筛选列表。

左侧进度随当前相机切换：“分割进度”统计已生成或已失败的采集占比，并单列已生成、失败和待处理数量；“掩码复核”统计已确认掩码占已生成掩码的比例。分割失败也计入已处理数量，因此任务完成 100% 时仍可能有失败记录。搜索和状态筛选只影响列表，不改变该相机的进度分母。正在分割时，页面随任务轮询更新采集状态和进度。

### 导出与下载分割失败记录

“导出筛选成果”除所选成功分割外，会同时生成 `分割失败记录.csv` 和 `分割失败记录.json`，记录当前成果中的全部未解决失败项，不受“保留／淘汰／全部”等导出范围限制。导出的 `筛选记录.csv` 也会包含这些失败行。失败没有掩码可复制，因此只有记录，不复制原始图像，也不会混入可编辑掩码的采集清单。无失败时仍生成只有表头的失败 CSV 和空 JSON 清单。

顶部“下载筛选记录 CSV”会列出当前成果的全部采集及随成果保留的失败项，并新增“相机类型”“采集相对路径”“分割失败原因”列；失败行的分割状态为“分割失败”，成果目录留空，原始路径可用于定位问题采集。CSV 使用 UTF-8 BOM，支持 Excel 打开及中文、多行错误原因。重新打开或再次导出筛选成果时，失败记录仍会保留；已有成功掩码的采集会从旧失败记录中排除。

顶部下载与成果导出的所有筛选 CSV 均包含“猪头侧方向”列，按已保存记录显示“左侧／右侧／上侧／下侧”。缺少方向、未填写或尚未记录时统一显示“尚未记录”；附带的失败 CSV 使用同一列格式。
